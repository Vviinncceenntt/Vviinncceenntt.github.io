## Fix 1 — If `localhost:8081/` also hangs (Result B)

Metro is trying to reach `expo.dev` or `npm` during manifest generation and your network blocks it. Disable the network checks:

```bash
cd /c/path/to/swiss-round-calculator/mobile
export REACT_NATIVE_PACKAGER_HOSTNAME=192.168.0.127
npx expo start --lan --offline --clear
```

The `--offline` flag tells Expo "don't phone home for anything". Manifest is generated locally.

## Fix 2 — If `localhost:8081/` works but iPhone still fails (Result A)

iOS **App Transport Security** is silently dropping anything except small responses to your Wi-Fi. The manifest is ~2-5 KB, much bigger than the 23-byte `/status`. Two workarounds:

### 2a — Sign in to Expo CLI, then retry tunnel
The reason your tunnel said `pxtev-c-**anonymous**-8081` is that the CLI is not logged in even though Expo Go on iPhone is. Anonymous tunnels are heavily throttled. Log in:

```bash
npx expo login
```
Enter your Expo email + password (same one you use in Expo Go on iPhone). Then:

```bash
npx expo start --tunnel --clear
```

The new QR will have `pxtev-c-<your-username>-8081.exp.direct` — authenticated tunnels get a much higher bandwidth and reliability tier.

### 2b — Use an **EAS development build** (the bulletproof path)

This is what professional devs use on Windows because it bypasses Expo Go entirely and avoids every issue you've hit. Steps:

```bash
npm install -g eas-cli
npx expo login                          # if not already
eas build --platform ios --profile development
```

EAS will:
1. Ask you to log in with your Apple ID (free Apple Developer account is enough)
2. Provision a certificate for you (handled in the cloud)
3. Build an `.ipa` on Apple's Mac servers (~15-20 minutes)
4. Give you a QR code/link to install it directly on your iPhone

The resulting app is **your custom build of Expo Go** with the project's exact native modules. After install, run:

```bash
npx expo start --dev-client --lan --clear
```

…and your installed dev-client app will load the JS bundle perfectly every time (no manifest dance, no Expo Go limits, supports `react-native-purchases` properly too).

I know "15-20 min cloud build" sounds like overkill for "I just want to see it", but Expo Go on iOS in 2026 has gotten so restrictive that EAS dev client is now the recommended path for serious testing on Windows. The build happens **once**; after that, `expo start --dev-client` is identical to `expo start` but never has the Expo Go problems.
