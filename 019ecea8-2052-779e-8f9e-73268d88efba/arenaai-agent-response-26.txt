### What `font-display: block` does

The browser hides the text completely (renders blank space) for up to ~3 seconds while waiting for the TTF to download. If the font arrives in time, text paints with the correct typeface; if not, it falls back to the system font. Crucially, **once the TTF eventually downloads, the text re-renders with the custom font** — and it stays that way for the rest of the session. No more "sometimes I see Chiron, sometimes I see fallback" inconsistency.

The trade-off is a brief blank moment on first paint over slow networks, but you've explicitly said you prefer that over inconsistent rendering — same call as your GitHub Pages source.

### TTF-only rationale (now in the README header)

Same TTF file feeds three different consumers:
1. Browser `@font-face` (the web build).
2. React-Native `require()` (mobile bundle).
3. Embedded inside SVG masters via `<style>@font-face{src:url(...ttf)}</style>` (app icon, splash screens — see `generate-assets.sh`).

WOFF/WOFF2 are smaller for the browser path but **resvg-js, ImageMagick, and Inkscape don't all recognise them when embedded in SVG**. Standardising on TTF keeps every part of the pipeline using the same exact bytes.
