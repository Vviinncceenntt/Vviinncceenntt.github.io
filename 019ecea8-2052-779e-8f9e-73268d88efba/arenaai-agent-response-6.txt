## Summary of fixes

### 1. Real SVG icons for the bottom navigation
**Root cause:** Initial React-Native `BottomNav.js` used inline placeholder SVGs (the "fx", gear, document, circle dummies). The web version used Unicode glyphs (ƒ𝓍 ⚙ § ◯).

**Fix:**
- Downloaded all 4 icons specified in the brief and saved them under:
  - `mobile/assets/icons/` (for React Native)
  - `web/assets/icons/` (for the web build)
- **Mobile**: New `src/constants/icons.js` (auto-generated by `scripts/inline-icons.js`) exports each SVG as a raw string consumed by `<SvgXml/>` from `react-native-svg`. A small `recolour()` helper rewrites pure-black `fill`/`stroke` attributes to the current nav text colour so icons follow light/dark mode while preserving multi-colour artwork (e.g. the gear's `#72a7cf` cyan accent).
- **Web**: New `web/js/icons.js` exports each SVG as a base-64 `data:image/svg+xml;...` URI; `<img class="ico">` elements in `index.html` receive their `src` at runtime. Dark mode applies `filter: invert(1) hue-rotate(180deg)` to keep them visible on the dark navbar.
- A regenerator script `mobile/scripts/inline-icons.js` lets you drop new SVGs into the icons folder and rebuild the JS exports with `node scripts/inline-icons.js`.

### 2. Iframe dark-mode mask removed
**Root cause:** I had `background: #111` AND `filter: invert(1) hue-rotate(180deg)` together. The CSS filter is applied to the iframe *and its background*, so `#111` (almost-black) got inverted into `#EEE` (light grey) — that's the light grey mask you saw.

**Fix:** Keep `background: #FFFFFF` in both light AND dark modes. In light mode it stays white. In dark mode the filter inverts it to black, which matches the inverted body content of the embedded page. The visible result: dark grey page background with light text, no mask.

The React-Native `WebView` path (which uses real CSS injection rather than a filter) keeps `#111` because that's the genuine post-injection page background and no inversion is happening.

### 3. True triangular 3-state circular toggle switch slider
**Root cause:** v1.0.2 used three separate vertex dots that you tapped — which is morphologically a button cluster, not a slider.

**Fix:** Rebuilt as a single continuous slider:
- **One sliding circular knob** travels along the triangle's perimeter.
- The triangle outline IS the track (`<polygon stroke="…" fill="none">`).
- **Drag** the knob anywhere on the track — it follows your finger using segment-distance snapping (closest-point-on-segment math) so it always stays on an edge.
- On release, the knob springs to the **nearest vertex** (Auto / Landscape Left / Portrait).
- Or **tap** any vertex glyph (A/L/P) to jump the knob to it.
- Web uses Pointer Events (with Mouse + Touch fallbacks); RN uses `PanResponder` + `Animated.spring`.

A side legend (zh-on-top-of-en) highlights the active letter so you know exactly which orientation the slider currently selects.
