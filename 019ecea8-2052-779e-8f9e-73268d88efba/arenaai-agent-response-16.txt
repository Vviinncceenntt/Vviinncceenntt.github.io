Found it. **Metro never logs the iPhone's request because the iPhone is hitting a wrong address.** Here's why:

When Expo Go opens `exp://192.168.0.127:8081`, it doesn't just download the bundle. It first fetches a **manifest** (a JSON blob from `http://192.168.0.127:8081`), reads the `bundleUrl` field inside, and then fetches the bundle from that URL. Metro generates the manifest by guessing your PC's hostname — and after you installed Bonjour, it's probably guessing wrong now (typically your PC's `.local` mDNS name, or an unreachable hostname like `Vincent-PC.lan`). Your iPhone can't resolve that → silent timeout → Metro never sees the request.

## Two-step fix

### Step 1 — Confirm the diagnosis (10 s)

On your iPhone Safari, open this **without** the `exp://` prefix:

```
http://192.168.0.127:8081
```

You'll see a JSON response (it might download as a file, same as `/status` did). Open it in Files → look for the `bundleUrl` line. If it says something like:

```json
"bundleUrl": "http://Vincent-PC.local:8081/...",
```
or
```json
"bundleUrl": "http://192.168.56.1:8081/...",   // a virtual adapter
```

…then yes, Metro is announcing itself under a name your iPhone can't reach. (If `bundleUrl` already shows `192.168.0.127`, then it's a different problem — see Step 3.)

### Step 2 — Force Metro to use your real Wi-Fi IP

In Git Bash, **before** starting Expo:

```bash
cd /c/path/to/swiss-round-calculator/mobile
export REACT_NATIVE_PACKAGER_HOSTNAME=192.168.0.127
npx expo start --lan --clear
```

(In cmd.exe, the syntax is `set REACT_NATIVE_PACKAGER_HOSTNAME=192.168.0.127` on one line, then `npx expo start --lan --clear`.)

Now every URL in the manifest will use the explicit `192.168.0.127`. Reopen `exp://192.168.0.127:8081` in iPhone Safari → Open in Expo Go.

This time you'll see **iOS Bundling 1/598…** start scrolling in the Git Bash window within 2-3 seconds.

### Step 3 — If `bundleUrl` already showed the correct IP

Then the problem is the iPhone connects but Expo Go (a sandboxed app) is blocked from making outbound HTTP requests to non-secure addresses by **iOS App Transport Security**. Try the experimental newer entrypoint in Expo SDK 54 — it serves over HTTPS via a self-signed certificate Expo Go trusts:

```bash
npx expo start --lan --clear --dev-client
```

Or, easier, switch back to the **ngrok tunnel** (which IS HTTPS):

```bash
npx expo start --tunnel --clear
```

ngrok will now actually work because your bundle IS small enough to push through it once Metro has it cached.

## Why pre-warming "worked" in Chrome but not on iPhone

When Chrome on your PC loaded `http://192.168.0.127:8081/index.bundle?platform=ios&dev=true&minify=false`, it **bypassed the manifest step** by going directly to the bundle URL with explicit query params. Metro served it fine because the request reached it. Expo Go on iPhone follows the manifest-then-bundle dance, so a bad manifest hostname stops the whole flow before any HTTP request leaves the phone.

The fact that nothing appears in Metro logs when Expo Go tries is the diagnostic clincher — **the request literally isn't reaching Metro**.
