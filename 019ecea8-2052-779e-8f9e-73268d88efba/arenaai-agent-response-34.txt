## Issue 2 — Subscripts misaligned: last sub vertically centred, first floating at top

Let me check the current code:

The bug: at `LmaxRmin = L_{max_{R_{min}}}`, the rendered flex children are `[L, max, R, min]` all as siblings of the same row, each with its own `marginTop`. The `max` gets `marginTop = 0.35*baseSize`, the `R` gets the same (depth 1), and `min` gets `marginTop = 0.6*baseSize` (depth 2). With `alignItems: 'flex-start'`, they all start from the top but with different push-downs — but the parent row's height is determined by the TALLEST child, which is `L` at full size. So short subs get `marginTop` from the top of the row → they end up LOWER but the visual baseline mismatch is jarring.

The real subscript convention: `L_{max_{R_{min}}}` should render as:
```
L max  R  min      ← logical levels
    (each subsequent is smaller and lower than its parent base)
```

But the LAYOUT problem is that the user perceives subs as "centred". That's because once we have `marginTop`, each level's child sits at its own y-offset, but `alignItems: flex-start` aligns each independently and the row height grows to the max of (size + marginTop). The short subs LOOK centred because the row is taller than they are.

Better approach: render the WHOLE notation as a single inline `<Text>` with nested `<Text>` children, exploiting RN's actual support for **inline text nesting** plus `verticalAlign` (RN 0.74+) or simply smaller `fontSize` (which naturally aligns to baseline). Let me use that approach:
