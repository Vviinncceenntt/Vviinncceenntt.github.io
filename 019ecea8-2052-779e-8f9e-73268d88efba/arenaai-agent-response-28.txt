## Summary — incorporating your hard-won wisdom

You explained two things from your alpha/beta history that I should have respected the first time:

> ### 1. Why iframe is the right choice
> "I tried to use Get Element to fetch the pages … The result was inconsistent and unstable… Then, I tried iframe which always delivered the fonts of the source page."

I removed all "Get element + restyle" code and all base64 font injection. Every menu now uses a plain `<iframe>` (web) or `<WebView>` (native) pointed at the canonical GitHub Pages URL. The source's own `style.css` (your `@font-face` declarations confirmed above) supplies every font. **No bouncing, no injection, no oversized bundle.**

> ### 2. Why base64 font injection was wrong
> "Inlining as base64 makes the package too big for transferring to mobile Phone Expo Go (time out)."

Deleted `loadFontBase64.js` and `injectFont()`. The mobile JS bundle is now small again — Expo Go can ferry it without timing out.

> ### 3. Functions and Wong system have no date line
> Cache refresh policy is now split: Legal pages use the conservative date-comparison refresh; Functions and Wong system refresh unconditionally on each visit (cheap, harmless since they rarely change).
