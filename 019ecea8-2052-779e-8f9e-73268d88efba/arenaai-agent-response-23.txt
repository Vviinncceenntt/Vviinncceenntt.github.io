## Summary of fixes

### 1️⃣ Custom fonts now load on iPhone Safari
**Root cause:** The TTFs in `web/assets/fonts/` were 4-byte placeholders I committed during initial scaffolding ("populate them before publishing" was a TODO item, but you tested before that step).

**Fix:** Downloaded the real Chiron Sung HK, Chiron Hei HK, Chiron GoRound TC, and The Peak Font Plus typefaces. Subset each to **just the 318 CJK + ASCII characters the app actually uses** using `pyftsubset`. Result:

| Format | Before | After |
|---|---|---|
| TTF total | 0.016 KB (placeholders) | 970 KB (subset, real glyphs) |
| WOFF2 total | (none) | 460 KB |

Web uses WOFF2 first with TTF fallback, supported on Safari 11+ / iOS 11+. Mobile uses the subset TTFs directly. The CSS comment in `web/css/fonts.css` documents how to regenerate after replacing the masters.

### 2️⃣ "Copy Output" works in Safari now
**Root cause:** Safari blocks `navigator.clipboard.writeText` on insecure origins. Your dev server is `http://192.168.0.127:8765` (plain HTTP, not HTTPS, not `localhost`), so the API silently failed. Chrome is more permissive over LAN HTTP, so it worked there.

**Fix:** Added a `copyToClipboard()` helper that tries the modern API first (works on `https://` and `localhost`), then falls back to the legacy `document.execCommand('copy')` inside an off-screen `<textarea>`. The fallback includes the iOS-specific focus + `setSelectionRange` dance that mobile Safari requires.

### 3️⃣ Close button "✕" now perfectly centred on Safari
**Root cause:** Without an explicit font family, Safari uses **Apple Color Emoji** as fallback for U+2715 ✕, which has a heavy right-anchor in its metrics. The cross drew flush to the right edge of the circle instead of centred.

**Fix:** Switched the button to flex centering (`display: inline-flex; align-items: center; justify-content: center`) AND forced `font-family: 'Helvetica Neue', Arial, sans-serif` so Safari uses a glyph with symmetric metrics, not Apple Color Emoji.

### 4️⃣ Triangular orientation slider — better visual identity
The slider is **intentionally disabled on web** per your spec ("(N/A on web)"). Visual updates so it reads as a slider (matching the theme switch styling) even while disabled:

- **Knob**: white disc with `2px solid var(--primary)` border + soft shadow + inset highlight — matches the round handle on the theme toggle switch.
- **Track**: thick (`6px`) rounded polygon using the same `--switch-track-off` colour as the theme switch track; turns into the active `--switch-track-on` colour while being dragged (on native).
- **Disabled state on web**: track becomes a **dashed line**, knob loses its shadow, cursor becomes `not-allowed`. Now it's visually unambiguous that it's a disabled slider, not an idle button cluster.
