Found it. Look at the Python output:

```
Serving HTTP on ::  port 8765 (http://[::]:8765/) ...
```

The `::` is the **IPv6 wildcard address**. Python 3.14 (your version) now defaults to IPv6-only on Windows. Your iPhone is connecting via the **IPv4** address `192.168.0.127`, which is on a completely different stack — so the request never reaches Python.

## Fix — force IPv4

Stop the current server (`Ctrl+C` in the Python window), then:

```bash
cd /c/path/to/swiss-round-calculator/web
python -m http.server 8765 --bind 0.0.0.0
```

You should now see:

```
Serving HTTP on 0.0.0.0 port 8765 (http://0.0.0.0:8765/) ...
```

`0.0.0.0` is the IPv4 wildcard — it accepts connections from any interface, including your Wi-Fi.

Now on iPhone Safari:
```
http://192.168.0.127:8765
```

The bilingual **瑞士制輪數計算機 / Swiss Round Calculator** onboarding screen should appear in ~2 seconds.

## Quick sanity check first

On your PC, open Chrome and visit `http://localhost:8765` — that should show a directory listing or the `index.html` content even before the bind fix. If it does, the bind fix above is the only thing needed for iPhone to see it.

## If Safari still times out after the bind fix

It's almost certainly the firewall rule not matching the IPv4 socket. Double-check in PowerShell as Administrator:

```powershell
Get-NetFirewallRule -DisplayName "Local web preview 8765" | Format-List
```

If the rule exists but iPhone still can't connect, run this nuclear-option test from a **second Git Bash window** while Python is still running:

```bash
curl http://192.168.0.127:8765
```

- ✅ Returns the HTML → firewall is fine, iPhone problem (try iPhone Wi-Fi off/on).
- ❌ Times out / connection refused → firewall is still blocking; tell me the curl error.

---

## TL;DR

```bash
python -m http.server 8765 --bind 0.0.0.0
```

The missing `--bind 0.0.0.0` is the only thing wrong. Python 3.14 silently changed the default to IPv6.
