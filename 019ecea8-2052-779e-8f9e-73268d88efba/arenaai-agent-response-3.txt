## Summary

### 1️⃣ `generate-assets.sh` — "參數無效 - none" with ImageMagick `convert`
On Windows, ImageMagick 6 (`convert`) rejects some flag orderings, hence the Chinese error "Invalid parameter - none". The script now tries **four invocation patterns** in order, picking the first that works:
- **A** — `magick -density 384 -background transparent SRC -resize WxH OUT` (flags before input)
- **B** — `magick -density 384 SRC -resize WxH OUT` (drops the `-background` flag entirely; works when MSVG/RSVG transparency is missing)
- **C** — `magick -density 384 svg:SRC -resize WxH png:OUT` (explicit format prefixes for IM6)
- **D** — `magick SRC OUT` (simplest possible form) then a separate resize pass

If all four fail it skips the file but doesn't crash. Re-run the script and the PNGs should generate.

### 2️⃣ Clarified `app.json._masterAssets` / `app.json.extra` aren't files
These are **JSON keys inside `mobile/app.json`** at lines 66–75 (`extra`) and 77–87 (`_masterAssets`). I updated `TODO.md` to make this unambiguous.

### 3️⃣ Triangular Orientation toggle — restored as a true triangle UI
**Web:** SVG-drawn triangle outline with three vertex pills (A, L, P) and a coloured circular **knob** that animates between vertices when you tap. A bilingual legend (zh-on-top-of-en) sits beside it explaining each letter. CSS:
```
        A (top vertex: Auto)
       / \
      /   \
     /     \
    L───────P
 (bot-left)  (bot-right)
```
**React Native:** New `<OrientTriangle>` component using `react-native-svg` with a `<Polygon>` outline, three `<Pressable>` vertex pills, and an animated knob that translates between vertices. Replaces the old segmented look in `SettingsMenu.js`.

Both remain visibly grayed-out on web (per spec), but the shape is now a real triangle.

### 4️⃣ Dark mode readability for Functions / Legal / Wong system menus
**Web:** Cross-origin iframes can't be styled, so applied a CSS filter directly on the `<iframe>` element when dark mode is active:
```css
[data-theme="dark"] .modal iframe {
  background: #111;
  filter: invert(1) hue-rotate(180deg);
}
```
The `hue-rotate(180deg)` keeps any coloured glyphs near their original hue after inversion.

**React Native (WebView):** Same-origin so we can do it properly — a new `src/utils/webviewDarkMode.js` exports an `INJECTED_DARK` payload that injects a `<style>` block:
- `body { background:#111; color:#EEE; }`
- Forces light text on dark for all major tags (`h1-h6`, `p`, `li`, `td`, `code`, `pre`, …)
- Preserves custom fonts (no font overrides)
- Falls back to `filter: invert(1) hue-rotate(180deg)` for any nested iframes
- Removed automatically on theme switch back to light via `INJECTED_LIGHT`

Wired into all three menus (`FunctionsMenu`, `LegalMenu`, `WongMenu`) via WebView's `injectedJavaScript` + `injectedJavaScriptBeforeContentLoaded` props.
